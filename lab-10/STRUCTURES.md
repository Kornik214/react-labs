# ЛР-10. Структури папок

Ці таблиці заповнюєте ви: рядок «Де живе кошик» після кожної структури
(§4.3–§4.6) і «Вибір структури» наприкінці (§4.7). Рядок «Пакет» — лише якщо
виконуєте додаткове завдання §4.9. Як рахувати теки, описано в інструкції,
§4.2.

## Де живе кошик

У яких теках лежать шість файлів кошика: сховище, `useCart`,
`AddToCartButton`, `CartLine`, сторінка кошика й шапка з лічильником.
«Тек» — скільки їх, «Теки» — їхні шляхи через кому.

| Структура                  | Тек | Теки                                                                                                                         |
| -------------------------- | --- | ---------------------------------------------------------------------------------------------------------------------------- |
| За типом файлів (§4.3)     | 4   | `src/store/`, `src/hooks/`, `src/components/`, `src/pages/`                                                                  |
| За маршрутами (§4.4)       | 5   | `src/shared/store/`, `src/shared/hooks/`, `src/shared/components/`, `src/routes/cart/`, `src/app/`                           |
| За функціональністю (§4.5) | 5   | `src/features/cart/stores/`, `src/features/cart/hooks/`, `src/features/cart/components/`, `src/app/routes/cart/`, `src/app/` |
| FSD (§4.6)                 | 4   | `src/entities/cart/model/`, `src/features/add-to-cart/ui/`, `src/pages/cart/ui/`, `src/widgets/app-header/ui/`               |     |     |     |
| Пакет (§4.9)               |     |                                                                                                                              |

## Вибір структури

Описи проєктів, з чого обирати і як пояснити вибір — в інструкції, §4.7.
«Чому»: що в проєкті важливо і чому обрана структура для цього підходить.

| Проєкт                             | Структура           | Чому                                                                                                                                                           |
| ---------------------------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Прототип на хакатоні            | За типом файлів     | Мало файлів і 1–2 дні розробки: найшвидший старт без витрат часу на проєктування меж шарів і Public API.                                                       |
| 2. Блог і документація на Next.js  | За маршрутами       | Контент і сторінки прив'язані до URL, маршрути майже не ділять складну бізнес-логіку між собою, а файловий роутинг Next.js працює з коробки.                   |
| 3. Адмінка для бариста             | За функціональністю | Багато незалежних робочих сценаріїв (замовлення, меню, залишки, зміни), які зручно ізолювати у фічі без надлишкової ієрархії FSD.                              |
| 4. Інтернет-магазин кави           | FSD                 | Складний домен зі спільними сутностями (товар, кошик), перевикористовуваними діями та віджетами на різних сторінках — потрібні суворі межі шарів і Public API. |
| 5. Три застосунки мережі кав'ярень | Пакетна (монорепо)  | Спільні UI-компоненти, моделі даних і бізнес-логіку (кошик, авторизація, меню) потрібно перевикористовувати між кількома окремими застосунками.                |
